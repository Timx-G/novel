# 《不要怕》从这里开始

这里是《不要怕》的写作空间。这本真实故事与随笔集首先写给你自己：记录成长中的经历与感受，梳理所思所悟，留下日后可以回看的认识和提醒。

“不要怕”是你对自己说的话：希望面对人生中的经历、困难和挫折时，都能勇敢面对。真实的害怕和暂时没有答案，也可以写下来。

当相似的困难再次出现，希望你能从过去的文字中找到曾经的经验，辨认眼前的处境，再决定怎样往前走。待这些记录渐渐成书，也期待与后来读到它的人彼此共勉。

你可以直接写，也可以把想法、回忆或片段交给我协助整理。经历、立场与表达取舍由你决定。先独立成篇，再根据实际内容安排全书顺序。

## 今天就可以开始

- 只有一句话、一个念头：打开[随手记](01-素材/随手记.md)，接着往下写。
- 有一段较长的回忆：在[素材目录](01-素材/)新建一个 `.md` 文件，先保存你记得的内容。
- 已经想写成一篇文章：在[正文目录](02-正文/)新建 `文章标题.md`，写上标题和段落即可。

这些文件都可以直接修改，不需要先来聊天，也不要求按全书顺序写作。素材允许零散，正文也允许从中间的一段开始。

## 用什么格式写

原稿统一使用 **UTF-8 编码的 Markdown 文件，扩展名是 `.md`**。用现有的文本编辑器打开和保存即可。

最常用的写法只有三种：`# 标题` 表示文章标题，`## 小标题` 表示文内分节，段落之间留一个空行。普通文字可以直接写，不需要学习更多语法，也不必手动给每段加空格缩进。

下面是可以复制到新正文文件里的空白模板；方括号中的文字是提示，写作时替换或删掉。

```markdown
# [文章标题]

[从你想写的第一个场景或念头开始。]

[下一段。]
```

文章文件名只写标题，例如 `文章标题.md`。阅读顺序放在全书目录里管理，改顺序时不用给文件重新编号。

## 怎样保存一份素材

较长的素材可以命名为 `记录日期-素材短标题.md`。这里的日期表示你记录它的时间，事情发生的时间在文内另写；记不清时就写“待确认”。

下面的提示都可以省略，只保留对这段素材有帮助的部分。

```markdown
# [素材短标题]

记录日期：
事情发生的大致时间、地点：
人物及关系：

## 我记得的事情

## 当时的感受／现在的看法

## 记不清、需要确认的地方
```

如果素材来自他人的讲述或参考资料，可以顺手记下来源。涉及真实人物的姓名或化名，由你决定。原始记忆、听闻与自己的理解可以并存，写清它们各自是什么即可。

## 怎样让我参与

告诉我文章的位置和你需要的帮助，例如：

- “读一下这篇，指出人物关系或叙述不清楚的地方，先给意见。”
- “保留我的语气，直接做一次轻度润色。”
- “结合这几份素材，帮我调整这篇文章的结构。”
- “看看这几篇之间有什么联系，提出全书顺序建议。”

我会依据你的材料工作，区分原文事实、个人感受与编辑建议。不能确认的细节会留下问题，不补写成已经发生过的事情。

正文以 `02-正文` 中的文件为准，素材中的原始表达保留。涉及结构重排、大幅删减或叙述角度变化时，先把旧稿存入 `99-归档`，用“保存日期-文章标题-改写前.md”区分；同名时增加序号。

## 用写作 skill 接着写

这里已接入[人生故事与随笔成书](.agents/skills/life-writing/SKILL.md)。你可以提供零散想法、故事片段或原稿，不必先把语言组织好。例如：

- “用 `$life-writing` 和我讨论这段想法，先别写文件。”
- “用 `$life-writing` 把这些真实素材整理成一篇短文，先在回复中给我看。”
- “用 `$life-writing` 修改指定的正文文件，保留我的语气，并同步写作进度。”
- “继续《不要怕》，先读协作记录，告诉我上次停在哪里。”

从当前书籍目录或父级 `novel` 目录开始协作，都有同一份 skill 入口。若技能列表尚未显示，可以直接让助手读取上面的链接。以后在新的聊天里，也可以指定本书目录接着工作。

仅讨论时在回复中交流；完成获授权的文件编辑后，助手同步目录和必要的[协作记录](00-全书规划/协作记录.md)。篇目未完成也能保留进度，不需要每次重新介绍整本书。

## 按 SDD 持续改稿

先用三份全局 Spec 保持方向一致，再逐篇组织材料、写稿和修改。每篇开始处理时建立写作要求（Requirements）、展开计划（Plan）和验收记录（Validation）；具体位置与流程见[Roadmap](specs/roadmap.md)。

你可以说：“按 SDD 开始《欠了十年的奥利奥》，根据现有材料建立 Spec，先在聊天里给我一版短稿。”也可以直接指定修改现有稿件；已有授权的工作会连同必要记录一起完成，不需要为每个步骤重复确认。

目前已登记五个你认可、篇名暂定的[篇目](00-全书规划/全书目录.md)；[《为什么要把这些写下来》](02-正文/为什么要把这些写下来.md) 已形成第一版，其余四篇待写。没有正文的 Spec 和提纲不计为作品，写作顺序与最终阅读顺序分别安排。

一章可以持续修改，每轮只交付约定的内容。初稿完成当前轮的核对后，可以作为阶段版本整合进 main；开始下一章不必等前一章定稿。后续材料影响前文时，从最新 main 开修订分支，更新原来的正文和 Spec，也可以在一轮里同时修订相关的多章。章节成熟度、当轮交付和实际 Git 合并状态分别记录，详见 Roadmap。

## 以后遇到相似的困难

可以先从[全书目录](00-全书规划/全书目录.md)中的“按问题回看”找到相关篇目，再回到文章里看当时的情境、做法和认识。索引会随着真实篇目逐步补充，现在留空。

回看时，留意这次与上次有什么不同、过去哪些经验仍然适用。如果有了新的理解，可以继续写下来；还没有答案，也可以先记下困惑。

## 全书目录和版本

新建文章后，可以在[全书目录](00-全书规划/全书目录.md)登记篇名、链接和状态。暂时不知道放在哪里，就先留作候选篇目。篇目清单、写作状态和阅读顺序需要手动维护，也可以交给我更新；文件新增或改名后，核对条目与链接是否仍然对应。

等有几篇可读文章后，再讨论分部、篇章顺序和过渡。现阶段目录保持开放，不要求每篇都落在事先划好的主题里。

后期需要审稿或分享时，从正文生成 `.docx` 或 PDF，放入 `04-导出`。导出稿上的修改意见整理回 Markdown 原稿，保持一套主要稿件。当前目录尚未配置自动排版、导出或同步。

本地目录和旧稿归档不等于异地备份。长期保存时，另行选择备份位置；目前尚未配置备份。
