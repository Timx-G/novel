## 2. 起草第一版（后续）

开始条件：作者要求进入本篇起草；沿用当前 Spec，结合届时新增材料，不重复询问已经确定的目的与取舍。

- [ ] 核对本篇材料是否新增，必要时更新 Requirements 中的来源、事实与不确定性。
- [ ] 按下面的展开建议写一篇短初稿；顺序可调整，不要求固定段数。
- [ ] 按作者当次要求在聊天中交稿或保存。若要求保存，主要稿件使用 `02-正文/为什么要把这些写下来.md`，再把目录状态更新为“初稿”。

## 3. 对照材料与反馈修改（后续）

- [ ] 执行 Validation 中的稿件核对，记录实际结果与需要作者确认的表达。
- [ ] 交付初稿，接收作者对口吻、原意、详略和情绪分寸的反馈。
- [ ] 按反馈改稿；结构重排、大幅删减或视角变化前，按书籍约定完整归档旧稿。
- [ ] 将本篇反馈落实到对应句段与 Spec。只有作者明确认可为全书偏好时，才更新全局表达方式。

## 4. 留下可接续的版本（后续）

- [ ] 保存获授权保留的稿件，更新目录、Validation 和必要协作记录。
- [ ] 作者认可或明确授权定稿时，标为“暂定稿”；尚未反馈时如实保留“初稿”或“修改中”。
- [ ] 如稿件已有可回看的认识，再填写目录索引；不为填表额外制造经验或结论。

后续是否继续改这一篇、转入重逢篇或调整阅读顺序，按作者选择推进。本轮不以 Spec 完成代替篇章完成。
